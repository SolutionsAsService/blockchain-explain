16 terms

Glossary

Block
A batch of transactions, with a header that includes the previous block's hash.
Hash
A fixed-length fingerprint of some data, here SHA-256's 64 hexadecimal digits (0–9 and a–f). It is collision-resistant: finding two inputs with the same hash is infeasible, though not impossible in principle.
Merkle root
One hash that commits to a whole list of transactions, so a short proof can show that one transaction is in the list.
Stake
Tokens a validator locks up as a deposit. Its voting power grows with its stake, and it can lose some of the stake for breaking the rules.
Fork
Two competing versions of a chain's history. Some chains wait for one to win; CometBFT never produces one.
Validator
A computer that takes part in consensus, with voting power in proportion to its stake.
Finality
The point after which a block cannot be reversed. In CometBFT, the moment more than two thirds of the voting power precommit it.
Byzantine fault
A failure where a participant may do anything, including lie. BFT protocols survive these from fewer than a third of the voting power.
ABCI
The Application Blockchain Interface between CometBFT and the application above it.
Module
One part of a Cosmos SDK chain's logic and state, such as bank, staking or ibc.
Smart contract
A program stored on the chain, run by every validator with the same result.
EVM
The Ethereum Virtual Machine, which runs contract bytecode, usually compiled from Solidity.
Light client
A small program that follows another chain's headers and signatures, so it can check proofs from it.
Relayer
A program that carries IBC packets between chains. It needs no trust, because each packet carries a proof.
IBC
Inter-Blockchain Communication: the protocol Cosmos chains use to pass messages and tokens.
Layer 0
On this site, the connection between chains. Other projects use the term differently.
