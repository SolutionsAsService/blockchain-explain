A case study, in its own terms

Case study: Autheo

This site began as an explainer for Autheo. What follows is only how Autheo describes itself, set against the stack the other pages explain.

In Autheo's own terms

Autheo describes itself as a decentralized operating system for web, blockchain and AI. It says it combines a Cosmos SDK base, an EVM-compatible execution layer and CometBFT consensus, with decentralized identity, post-quantum cryptography and infrastructure for AI agents.

Source: this summary condenses version 1 of this site (2025), which was written from Autheo's own materials; its text is in the repository history. It is not a quotation from a dated Autheo page, so check Autheo's current materials for its own wording.

This site has not checked those claims against a running network, and it prints no figures about one. Read them as a description, and the other pages as the background that lets you judge it.

Where each claim sits on the stack

  • CometBFT consensus: the bottom layer. How it works.
  • Cosmos SDK base: the application framework. How it works.
  • EVM-compatible execution: the contract layer. How it works.
  • IBC interoperability, as Autheo's materials list it: connecting to other chains. How it works.
  • Post-quantum cryptography: cryptography meant to resist quantum computers. NIST standardized the first in 2024: ML-KEM for key exchange, and ML-DSA and SLH-DSA for signatures. NIST.
