Reading a project's claims

Case study: Autheo

This site began as an explainer for Autheo. Here is how Autheo describes itself, set against the parts the rest of the guide explains.

In Autheo's own terms

Autheo describes itself as a decentralized operating system for web, blockchain and AI. It says it combines a Cosmos SDK base, an EVM-compatible execution layer and CometBFT consensus, with IBC interoperability, decentralized identity, post-quantum cryptography and infrastructure for AI agents.

Source: this summary condenses version 1 of this site (2025), which was written from Autheo's own materials; its text is in the repository history. It is not a quotation from a dated Autheo page, so check Autheo's current materials for its own wording. This site has not checked the claims against a running network.

Where each claim sits

  • CometBFT consensus: BFT voting. Consensus.
  • Cosmos SDK base and IBC: an application-specific chain that talks to others by light client. Bridges, Chains compared.
  • EVM-compatible execution: Ethereum-style contracts. Smart contracts.
  • Post-quantum cryptography: cryptography meant to resist quantum computers. NIST standardized the first in 2024: ML-KEM for key exchange, and ML-DSA and SLH-DSA for signatures. NIST.
