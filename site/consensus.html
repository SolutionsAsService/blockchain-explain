Consensus: CometBFT

  1. AppsApplications
  2. EVMExecution
  3. Cosmos SDKApplication framework
  4. CometBFTConsensus

Many computers must agree on one history without trusting each other. CometBFT is the consensus engine Cosmos chains use for that.

What consensus decides

Every validator (a computer that takes part in agreeing) sees transactions arrive in a different order. Consensus decides one order, groups it into a block, and decides when that block is final: settled for good.

CometBFT (formerly Tendermint Core) works in rounds. One validator proposes a block. The others vote twice, first a prevote and then a precommit. A block is final as soon as validators holding more than two thirds of the voting power have precommitted it. So there is never a second, competing version of the chain (a fork) that you have to wait to see settled.

How many can fail

The guarantee holds as long as validators with fewer than one third of the voting power are faulty: crashed, lying or working together against the rest. That is the limit for any protocol of this kind, called Byzantine fault tolerance.

The table assumes every validator has equal voting power. On a real chain, power is proportional to stake: the chain's tokens a validator has locked up as a deposit it can lose if it cheats. So the third is a third of the stake, not of the machines.
