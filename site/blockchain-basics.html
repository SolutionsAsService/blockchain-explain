The bedrock, under every layer

The basics

A blockchain is a list of blocks, each holding the fingerprint of the one before, kept by many computers at once. Three ideas make it work. Each one below runs in your browser.

1 · Hashes2 · The chain3 · Merkle trees

1 · A hash is a fingerprint

SHA-256 turns any text into 64 hexadecimal digits. The same input always gives the same hash, and the smallest change gives a completely different one. It is collision-resistant: nobody knows how to find two inputs with the same hash.

SHA-256ef7797e13d3a75526946a3bcf00daec9fc9c9c4d51ddc7cc5df888f74dd434d1

Changing one letter, blockchain to Blockchain, changes the hash from ef7797e13d… to 625da44e4e…: 62 of the 64 digits differ.

2 · The chain

Each block's hash covers its number, its data and the previous block's hash: SHA-256(number | previous | data). Change any old block and its hash changes, so the next block's “previous” no longer matches. Edit a block below and watch the link after it break. Re-linking that block changes its hash too, so the break moves down the chain: to rewrite one block, you must rewrite every block after it.

3 · Merkle trees

A block's header does not list every transaction. It holds one Merkle root: hash each transaction, hash the hashes in pairs, and repeat until one is left. A short path of hashes then proves that one transaction is in the block, without the whole list.
