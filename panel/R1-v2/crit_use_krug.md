## Notes per test

**1. Five-second test (home, 1280x800 and 375x812).** PASS. What is it: the H1 "Blockchain, explained" and the one-line deck. What can I do: read the stack layer by layer. Where do I start: one dominant green "Start with the basics →" button, visible above the fold at both widths. A small point for "very basic": "Every hash on this site is computed as you read it" is jargon on the first screen; "Try it yourself: every example works live in your browser" would say the same in plain words. This is not an objection.

**2. Legibility probe.** Desktop PASS: the dotted line is labelled "a transaction travels down" and passes Apps, then EVM, Cosmos SDK and CometBFT, ending at Bedrock. The IBC pill visibly joins Chain A's Cosmos SDK to Chain B's Cosmos SDK (Chain B links to Autheo). Phone OBJECT: the mobile SVG has no "a transaction travels down" text and no "Chain A"/"Chain B". The dotted line is an unnamed mark, and the IBC arrow (about x=358 of 375) points at nothing. A first-time phone visitor cannot name what the bridge connects to. See fix (2).

**3. Navigation.** Current page: always clear. `aria-current="page"` with an underline in the desktop nav and the mobile menu, a layer rail on the layer pages ("Layer 1 of 4" with the active tile highlighted), and a page-specific `<title>` everywhere. The logo links home on all 10 pages, including about and 404. The mobile Menu (`<details>`/`<summary>`) opens and closes by tap, Enter and Space, and Tab moves straight into the links. Escape does not close it. That is minor and native `<details>` behaviour, so it is not an objection. Next topic: missing. The pages end in a "Further:" line of external links, and the only onward link on Basics is the inline word "consensus" in the demo caption. The phone header does not stick, so the way forward is a long scroll back to the top. See fix (1). Small inconsistency: Consensus says "Layer 1 of 4", but its rail shows 3 tiles (Apps has no page).

**4. Basics demos.** The hash demo and the Merkle demo are self-evident: you edit text and the fingerprint changes. In the chain demo, editing Block 1 works well: Block 2 gets a red dashed border, the stale "Previous" hash is struck through, and the label reads "broken: 'previous' no longer matches block 1". Pressing "Re-link the chain" then turns every block green at once with no sign of what changed. The copy promises that the break moves down the chain and that "you must rewrite every block after it", but the interaction hides exactly that cost. The button is also enabled and silent before any edit, and no status message is announced (no `aria-live`). See fix (3). Adding `role="status"` to the broken/linked summary would also cover screen readers.
